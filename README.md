# Minecraft 服务器监控插件 Plus

面向 AstrBot 的 Minecraft 服务器状态监控插件。可为多个 QQ 群分别配置服务器监控，在状态发生变化时发送通知，并生成最近 24 小时的玩家在线人数统计图。

[![AI Assisted](https://img.shields.io/badge/AI-GPT%20Assisted-10A37F?style=flat-square&logo=openai&logoColor=white)](#致谢与许可)

| 项目 | 要求 |
| --- | --- |
| 当前版本 | `v1.1.0` |
| AstrBot | `>=4.26.0` |
| 主要适配平台 | `aiocqhttp` |

完整版本记录见 [CHANGELOG.md](https://github.com/shenbimicro233/astrbot_plugin_apimcmc/blob/master/CHANGELOG.md)。

## 功能概览

- 为多个 QQ 群分别保存服务器地址、版本类型、查询源和通知格式。
- 支持 Java 版与基岩版服务器。
- 支持 `mcstatus.io` 和 `mcmotdapi`，每个群可以继承全局设置或单独选择。
- 仅在首次检测、服务器上下线或在线人数变化时发送状态通知。
- 支持完整、精简和自定义三种通知格式，并在 WebUI 中实时预览。
- 群成员可以随时查询服务器状态或查看最近 24 小时的在线人数统计图。
- WebUI 提供配置搜索、状态筛选、运行状态和日志查看。

## 快速开始

1. 在 AstrBot WebUI 中安装并启用插件。AstrBot 会自动检查并安装插件所需的运行依赖。
2. 打开「插件配置」，设置检查间隔、是否自动启动监控以及默认查询源。
3. 打开插件页「Minecraft服务器监控」，点击「添加配置」。
4. 填写 QQ 群号、服务器 IP、端口和服务器类型，按需选择查询源与消息格式。
5. 保存配置。若没有开启「自动启动监控」，请使用 `/start_server_monitor` 手动启动监控。

## 配置说明

配置分为 AstrBot 的全局「插件配置」和插件页中的每群配置。下表使用的名称与 WebUI 实际显示一致。

### 全局插件配置

| WebUI 选项 | 作用 | 默认值或建议 |
| --- | --- | --- |
| 检查间隔（秒） | 每隔多少秒检查一次所有已配置服务器 | 默认 `10`，建议 `10` 至 `60` 秒 |
| 自动启动监控 | 插件加载后自动启动所有已启用群组的监控 | 默认关闭 |
| API查询源 | 选择默认的服务器状态查询服务 | 默认 `mcstatus` |
| mcmotdapi 服务地址 | 使用 `mcmotdapi` 时连接的服务地址 | 默认 `motd.minebbs.com` |
| mcmotdapi 启用 HTTPS | 使用 `mcmotdapi` 时是否通过 HTTPS 连接 | 默认开启；内网自部署可关闭 |
| 简化消息格式 | 群配置未单独指定时，默认使用简短通知 | 默认关闭 |
| 统计图文字样式 | 选择普通中文（Fusion Pixel）、附魔台文字或系统/配置字体 | 默认「普通中文（Fusion Pixel）」；全部图表文字为中文并只使用内置 Fusion Pixel；附魔台文字只转换英文字母 |
| 统计图备用字体候选 | 按顺序填写系统字体名称或字体文件路径 | 默认留空；选择「系统/配置字体」或内置字体不可用时自动尝试跨平台字体 |

### 每群配置

在「插件页」→「Minecraft服务器监控」中添加或编辑配置。

| WebUI 选项 | 作用 | 说明 |
| --- | --- | --- |
| QQ 群号 | 接收通知并使用群指令的目标群 | 必填 |
| 服务器名称 | 查询结果和状态通知中显示的名称 | 默认「Minecraft服务器」；统计图不显示服务器名 |
| 服务器 IP | Minecraft 服务器的 IP 或域名 | 必填 |
| 端口 | Minecraft 服务器端口 | 默认 `19132` |
| 服务器类型 | 选择「基岩版 (Bedrock)」或「Java 版」 | 默认基岩版 |
| API 查询源 | 选择「全局默认」「mcstatus.io」或「mcmotdapi」 | 默认继承全局设置 |
| 启用监控 | 决定该群是否参与定时检查 | 默认开启 |
| mcmotdapi 服务地址 | 当前群使用的服务地址 | 仅选择 `mcmotdapi` 时显示；留空继承全局设置 |
| 启用 HTTPS | 当前群连接 `mcmotdapi` 时是否使用 HTTPS | 仅选择 `mcmotdapi` 时显示 |
| 消息格式 | 选择「完整」「精简」或「自定义」 | 默认完整 |

选择「自定义」后，可以勾选以下内容：

`在线状态图标`、`服务器名称`、`MOTD 描述`、`游戏版本`、`协议版本`、`在线/最大玩家`、`玩家列表`、`服务端软件`、`服务器类型`、`地图名称`、`更新时间`、`附加一言`

WebUI 会实时显示消息预览。通知中的字段顺序固定，不受勾选顺序影响。

## 可用指令

| 指令 | 权限 | 作用 |
| --- | --- | --- |
| `/start_server_monitor` | 管理员 | 启动全局监控任务，检查所有已启用且配置完整的群 |
| `/stop_server_monitor` | 管理员 | 停止全局监控任务 |
| `/查询` | 群成员 | 立即查询当前群配置的服务器，仅限群聊 |
| `/在线统计` | 群成员 | 返回当前群服务器最近 24 小时的在线人数统计图，仅限群聊 |
| `/重置监控` | 管理员 | 清除当前群的状态缓存，下次检查按首次检测处理 |

## 通知格式

| 格式 | 内容 | 一言 |
| --- | --- | --- |
| 完整 | 状态变化、服务器名称、MOTD、版本、在线人数、玩家列表、服务器类型和更新时间等 | 默认附带 |
| 精简 | 状态变化、服务器名称和在线人数摘要 | 不附带 |
| 自定义 | 仅显示在 WebUI 中勾选的内容 | 勾选「附加一言」时附带 |

每群在插件页选择的消息格式优先于全局「简化消息格式」；没有单独设置时才使用全局选项。

## 监控与在线统计

- 监控是一个全局任务，会并发检查所有已启用且配置完整的群。
- 第一次成功检查会发送初始状态；之后只在服务器上下线或在线人数发生变化时发送通知。
- `/查询` 会立即请求服务器状态，但不会代替定时监控任务。
- 在线统计复用定时监控的成功查询，不会额外请求服务器或 API。
- 每个 15 分钟时段只保留第一次成功观测，滚动窗口最多保留 96 个观测点。
- 网络或 API 请求失败不会写入观测；对应的 15 分钟时段会显示红色半透明的「缺失数据」遮罩，且不会被当作服务器离线；成功查询到离线状态时，在线人数记为 `0`。
- 图表不会连接跨越缺失时段的折线，也不会把缺失数据当作零。
- 纵轴始终从 `0` 开始，并以窗口内可见观测的最高在线人数为上限；服务器容量不会放大纵轴，全零时使用上限 `1` 保持图表有效。
- 连续且无缺口地确认服务器离线至少 30 分钟后，图表区域会显示红色半透明离线遮罩，不再绘制玩家折线、点或柱状统计；在线但零人的服务器不会触发遮罩。
- 统计图不显示服务器名称。「普通中文（Fusion Pixel）」的全部图表文字均为中文，并且只使用内置 Fusion Pixel 显示；「附魔台文字」只使用内置 Monocraft，将英文字母显示为 Standard Galactic Alphabet，数字和标点保持不变；「系统/配置字体」使用备用字体候选和系统回退字体。
- 内置字体或随附许可文件不可用时，「普通中文（Fusion Pixel）」会使用系统备用字体显示中文；「附魔台文字」会使用备用字体保留可读英文，不会显示无法识别的方框。
- 每个群只保留当前服务器目标和最近 24 小时的数据。更换服务器后会开始新的统计序列；图表横轴从最后一次成功观测向前推 24 小时，并以该观测为右端。

统计数据保存在 AstrBot 的插件数据目录中，插件更新、重载或重启不会主动删除有效数据。生成的临时统计图会在初始化、停止和后续渲染时自动清理。

## 查询源

| WebUI 选项 | 说明 | 默认地址 |
| --- | --- | --- |
| `mcstatus.io` | 公共 Minecraft 状态查询接口，无需自行部署 | `api.mcstatus.io` |
| `mcmotdapi` | 可使用自部署服务，也可使用默认公共实例 | `motd.minebbs.com` |

每群「API 查询源」选择「全局默认」时，会继承全局「API查询源」及相关连接设置。

## 使用须知

- 插件需要能够访问所选状态查询服务；启用一言的通知还需要访问一言服务。
- 使用自部署 `mcmotdapi` 时，请确认服务地址、HTTPS 设置和网络连通性正确。
- 机器人必须已加入目标 QQ 群，并拥有发送消息的权限。
- `/查询` 和 `/在线统计` 只能在已经添加服务器配置的群中使用。
- `/在线统计` 使用定时监控成功采集的数据；最近 24 小时内尚无成功观测时会提示先启动监控，不会生成空白图片。
- AstrBot 会在插件安装、更新及缺少依赖的恢复流程中自动处理运行依赖。若安装失败，请查看 AstrBot 平台日志中的网络、镜像和权限错误，并尝试 WebUI 提供的失败插件重载功能。

## 常见问题

### 自动监控没有启动

检查全局「自动启动监控」是否开启，并确认至少有一条已开启「启用监控」且 QQ 群号、服务器 IP、端口填写完整的群配置。也可以由管理员发送 `/start_server_monitor` 手动启动。

### `/在线统计` 没有返回图片

先确认当前群已经添加服务器配置，并让监控任务至少成功查询一次。已有数据在监控暂时停止后仍可查看；网络失败、API 失败和停止监控期间不会新增观测，会显示为红色半透明的「缺失数据」遮罩。

### 安装或更新后提示缺少 Pillow 或 aiohttp

AstrBot 正常情况下会自动安装运行依赖。若自动恢复仍失败，请检查平台日志中的网络、Python 包镜像和写入权限，然后使用 WebUI 的失败插件重载功能重试。

### 精简通知中没有一言

这是预期行为。完整格式默认附带一言，精简格式不附带。如需自定义简短内容并保留一言，请选择「自定义」并勾选「附加一言」。

### 消息没有发送到群里

检查群号、该群的「启用监控」开关、机器人发言权限和监控任务状态。机器人还需要先在目标群收到至少一条消息，才能缓存用于主动通知的会话信息。
