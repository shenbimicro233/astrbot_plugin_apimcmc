# Minecraft 服务器监控插件 Plus

面向 AstrBot 的 Minecraft 服务器状态监控插件：支持为多个 QQ 群分别配置服务器，定时检查状态变化并发送通知，同时生成最近 24 小时的在线人数统计图。

[![AI Assisted](https://img.shields.io/badge/AI-GPT%20Assisted-10A37F?style=flat-square&logo=openai&logoColor=white)](#致谢与许可)

| 项目 | 要求 |
| --- | --- |
| 当前版本 | `v1.3.0` |
| AstrBot | `>=4.26.0` |
| 适配平台 | `aiocqhttp`、QQ 官方（`qq_official` / `qq_official_webhook`） |

完整版本记录见 [CHANGELOG.md](https://github.com/shenbimicro233/astrbot_plugin_apimcmc/blob/master/CHANGELOG.md)。

## 功能

- 多群独立监控
- Java版（包括SRV）、基岩版等多种服务端类型监控
- 查询源可选 `mcstatus.io`、`mcmotdapi` 、 `本地直连`
- 可高度定制的通知格式
- 支持即时查询与统计图查询
- 服务器查询
- 支持 QQ 官方 `group_openid` 与每群多机器人选择
- Web管理页面

## 快速开始

1. 在 AstrBot WebUI 中安装并启用插件，运行依赖会自动安装。
2. 打开「插件配置」，设置检查间隔、是否自动启动监控以及默认查询源。
3. 在插件页「Minecraft服务器监控」点击「添加配置」，填写群标识、服务器 IP、端口和服务器类型；「服务器类型」下拉框直接包含 Java 版（启用 / 禁用 SRV 解析）两态，选择「启用 SRV 解析」时端口可留空。
4. 多机器人部署时可在「消息平台」中选择实例；留空由插件自动检测。保存配置后，若未开启「自动启动监控」，发送 `/启动监控` 或 `/start_server_monitor` 手动启动。

## 配置

配置分为全局「插件配置」和插件页中的每群配置，表中名称与 WebUI 显示一致。

### 全局插件配置

| WebUI 选项 | 作用 | 默认值 |
| --- | --- | --- |
| 检查间隔（秒） | 所有已配置服务器的检查频率 | `10`（建议 10–60） |
| 自动启动监控 | 插件加载后自动启动所有已启用群的监控 | 关闭 |
| API查询源 | 默认查询服务 | 本地直连 |
| mcmotdapi 服务地址 / 启用 HTTPS | 使用 `mcmotdapi` 时的连接设置 | `motd.minebbs.com` / 开启 |
| 简化消息格式 | 每群未单独指定时默认使用简短通知 | 关闭 |
| 查询同目标合并请求 | 并发查询同一目标时共享一次上游查询 | 开启 |
| 查询冷却时间（秒） | 按群和发送者限制已接受的 `/查询` 命令；`0` 关闭 | `5` |
| 查询最大并发数 | 同时执行的新上游查询请求上限，合法范围 `1`–`32` | `4` |
| 统计图文字样式 / 备用字体候选 | 图表字体样式与系统回退字体 | 普通中文（Unifont）/ 留空 |

### 每群配置

| WebUI 选项 | 说明 |
| --- | --- |
| 群标识 | 必填。传统 QQ 群填写正整数群号；QQ 官方群填写 `group_openid` |
| 消息平台 | 自动检测或指定 AstrBot 平台实例；传统群号自动优先 `aiocqhttp`，`group_openid` 自动优先 QQ 官方平台 |
| 服务器名称 | 默认「Minecraft服务器」；统计图不显示 |
| 服务器 IP | 必填 |
| 端口 | 默认 `19132`；选择「Java 版（启用 SRV 解析）」时可留空 |
| 服务器类型 | 基岩版 / Java 版（启用 / 禁用 SRV 解析），默认基岩版；SRV 策略由每群显式决定 |
| API 查询源 | 全局默认 / `mcstatus.io` / `mcmotdapi` / 本地直连，默认继承全局 |
| 启用监控 | 是否参与定时检查，默认开启 |
| mcmotdapi 服务地址 / 启用 HTTPS | 仅使用 `mcmotdapi` 时显示，留空继承全局 |
| 消息格式 | 完整 / 精简 / 自定义，默认完整 |

「自定义」格式提供在线、离线两个模板。点击变量按钮可将占位符插入当前光标位置；编辑后会实时显示与实际通知一致的在线、离线预览。

模板可自由调整文字、字段顺序和换行。空值或“未知”字段会被移除，产生的连续空行会自动折叠；在线或离线模板留空时使用内置默认模板。

可用变量还包括 `{change_msg}`，用于把本次服务器状态或玩家数量变化放在模板指定的位置；不写入该变量时不会显示这段变化信息。

### QQ 官方平台与多机器人选择

- AstrBot 的 QQ 官方 WebSocket 适配器平台 key 为 `qq_official`，Webhook 适配器为 `qq_official_webhook`。
- QQ 官方群消息使用不透明的 `group_openid`，它不是传统 QQ 群号。请从机器人收到的群消息或 AstrBot 日志中取得该值，并填入「群标识」。
- 建议先让机器人在目标群收到一条消息，再执行监控命令。QQ 官方适配器需要该群已有会话场景信息，后续主动通知才能正确选择群消息接口。
- 一个插件可同时连接 `aiocqhttp` 和 QQ 官方机器人。为每个群指定「消息平台」即可使用不同机器人；同一平台类型有多个实例时，也应显式选择实例 ID。
- 官方群中的命令回复会提及发送者；查询和统计图片优先以单条 Markdown 图文消息显示，素材处理失败时自动回退为文本与图片两条消息。
- 「自动检测」只负责选择平台实例，不会把传统群号转换为 `group_openid`，也不会建立跨平台群标识映射。

## 指令

| 指令 | 权限 | 作用 |
| --- | --- | --- |
| `/启动监控`（`/start_server_monitor`） | 管理员 | 启动全局监控，检查所有已启用且配置完整的群 |
| `/停止监控`（`/stop_server_monitor`） | 管理员 | 停止全局监控 |
| `/查询` | 群成员 | 查询当前群配置，或按 `java|bedrock` 与可选地址查询，并返回本地生成的状态图片（仅群聊） |
| `/在线统计` | 群成员 | 返回最近 24 小时在线人数统计图（仅群聊） |
| `/重置监控` | 管理员 | 清除当前群状态缓存，下次检查按首次检测处理 |

## 通知格式

| 格式 | 内容 | 一言 |
| --- | --- | --- |
| 完整 | 状态变化、MOTD、版本、在线人数等完整信息 | 默认附带 |
| 精简 | 状态变化、服务器名称与在线人数摘要 | 不附带 |
| 自定义 | 按在线 / 离线模板渲染文字、变量顺序和换行 | 生效模板含 `{hitokoto}` 时附带 |

每群选择的格式优先于全局「简化消息格式」。

## 监控与在线统计

- 全局监控任务会并发检查所有已启用且配置完整的群；首次成功检查发送初始状态，之后仅在上下线或人数变化时通知。
- 玩家变动只报告有玩家上线/下线，所有查询源均不解析或展示玩家名单。
- `/在线统计` 复用监控数据，不额外请求服务器或 API。
- `/查询` 会立即请求状态，但不替代定时监控，查询数据源自配置的查询源。
- 每 15 分钟保留第一次成功观测，滚动窗口最多 96 个观测点；失败请求记为缺失（红色半透明遮罩），不算离线；成功查询到离线时人数记为 `0`，图表不会跨越缺失时段连线。
- 连续无缺口离线至少 30 分钟后，图表显示离线遮罩；在线但零人不会触发。
- 纵轴从 `0` 开始，以窗口内可见观测的最高人数为上限（全零时用 `1`）。
- 更换服务器会开始新的 24 小时统计序列；数据保存在插件数据目录，更新、重载或重启不丢失，临时统计图会自动清理。

## 查询源

| 查询源 | 说明 | 默认地址 |
| --- | --- | --- |
| `mcstatus.io` | 公共状态查询接口；Java 版 SRV 由服务端自动处理，插件无法关闭 | `api.mcstatus.io` |
| `mcmotdapi` | 公共实例或自部署服务；Java SRV 由插件控制（启用 `srv=true`，禁用 `srv=false`） | `motd.minebbs.com` |
| 本地直连 | 机器人主机直接查询；启用时优先解析 `_minecraft._tcp` SRV 记录，失败回退配置端口或 `25565` | 无 |

- 每群选择「全局默认」时继承全局查询源及相关连接设置。
- Java 版 SRV 策略由每个群在「服务器类型」中显式选择（启用 / 禁用），适用于所有查询源；基岩版不使用 SRV。
- 本地直连需机器人主机能访问目标端口（Java 通常为 TCP `25565`，基岩版为 UDP `19132`）。云服务器、容器或 NAT 环境可能无法直连内网服务器，请改用 API 查询源。
- 查询图片的延迟只使用同一次结构化响应：`mcstatus.io` 不提供可用延迟，固定显示 `--`；`mcmotdapi` 仅显示上游返回的有效 `delay`，该值可能来自远端节点或缓存；本地直连显示同一次 Minecraft 协议响应的 RTT。

## 注意事项

- 插件需要能访问所选查询服务；带一言的通知还需要访问一言服务。
- 机器人需已加入目标群并拥有发言权限；主动通知需要群内至少收到过一条消息，QQ 官方平台尤其依赖该会话场景。
- `/查询`、`/在线统计` 仅在已添加服务器配置的群可用；`/在线统计` 需监控至少成功查询一次。
- `/查询` 支持无参数、`java|bedrock` 类型以及类型加地址三种形式；地址支持域名、IPv4、裸 IPv6 和 `[IPv6]:端口`。Java 地址未给端口时启用 SRV，基岩版未给端口时使用 `19132`。
- `/查询` 命令并发达到上限时会立即提示繁忙，不会排队或切换查询源；参数错误不会占用冷却，已接受的失败查询也会消耗冷却。
- 公共查询源可能存在服务端/CDN 缓存，人数变化通知可能存在延迟，属正常现象,推荐优先使用本地存储的方式查询。

## 常见问题

- **自动监控没有启动**：确认全局「自动启动监控」已开启、群配置完整且端口已填写（明确启用 SRV 解析的 Java 配置除外），或发送 `/启动监控` 手动启动。
- **`/在线统计` 没有返回图片**：确认当前群已添加配置，并让监控至少成功查询一次。
- **精简通知没有一言**：这是预期行为；如需保留一言，请选择「自定义」并在模板中插入 `{hitokoto}`。
- **自定义模板改乱了**：点击模板编辑区的「恢复默认」即可恢复内置在线、离线模板。
- **保存模板提示未知占位符**：变量名必须与 WebUI 提供的按钮一致；删除手工输入的未知变量后再保存。
- **消息没有发送到群里**：检查群标识、「消息平台」选择、「启用监控」开关、机器人发言权限和监控任务状态。QQ 官方群不要填写传统数字群号，应填写 `group_openid`。
- **QQ 官方群没有收到主动通知**：确认该群先向机器人发送过消息、群标识来自当前 bot 的 `group_openid`，且所选平台实例与接收消息的 bot 一致。
